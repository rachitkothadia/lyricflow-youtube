# Architecture — 0.8

`matching/identity.ts` supplies bounded identity hypotheses, creator-credit parsing, title normalization, search plans and match evidence to both lyric providers. Metadata keeps raw title/channel and all explicitly named performers. Genius preserves structured co-primary/featured credits; LRCLIB serialized credits use the same identity checks. Queries find candidates; separate strict evidence gates decide automatic selection. An identity key includes complete credits so updated metadata triggers a fresh lookup. No song-specific catalogue or lyrics are bundled.

Metadata → LRCLIB → Genius fallback through a fixed-origin native reader → inert HTML parser → local Romanization → compact Shadow DOM panel. Genius source URLs can also be supplied in options. Channel identity resolves song-first video titles. Explicit feature credits embedded in LRCLIB titles are retained as artist evidence; terminal player-status suffixes are normalized without stripping recording versions.

Generated Indic runs use familiar Latin letters instead of scholarly IAST marks. Devanagari defaults to Hindi-style final/medial schwa rules, normalizes composed/decomposed nukta letters, and uses readable nasal spellings. Explicit vowels and adjacent existing Latin text remain intact. The language selector offers literal Devanagari for non-Hindi readings; Hindi schwa rules never apply to other Indic scripts. Source words and timestamps remain in the data. These are labeled algorithmic reading aids, with no guarantee of every name, compound or sung pronunciation. Sanscript's `syncope` option operates in the reverse direction and does not solve Devanagari-to-Latin schwa deletion; see its [configuration](https://github.com/indic-transliteration/sanscript.js/blob/master/_autodocs/configuration.md) and [Devanagari script requirements](https://www.w3.org/TR/deva-lreq/).

The watch player's media clock takes priority over preview videos. Metadata waits briefly for its duration, then reselects an edition when real duration becomes available or changes materially. Advertisement durations and playback are excluded. Safe same-duration source timestamps take priority; different-length timing stays an explicit candidate. Untimed provider text can acquire source timestamps only when all lyric lines align.

Synchronization uses `video.currentTime - (recordingAlignment + fineDelay)`; seeking uses the inverse. Matching a currently heard line sets the recording alignment without seeking. Fine delay stays within ±10 seconds. Background-only storage RPCs validate and serialize local profiles, capped at 100, keyed by video ID plus a hash of source URL, recording duration, words and source timestamps. Navigation and generation guards reject stale profile/caption/provider replies.

Optional caption recovery reuses the current video's observed same-origin timedtext request. JSON3 cue/word offsets are source timestamps. Full normalized text must match, and every lyric start must have an actual caption boundary; no missing boundaries are interpolated. Original lyric text and attribution remain, with a separate timing source link. Caption state is restored on completion or cancellation. This path has deterministic browser coverage; actual caption availability remains upstream-dependent.

Chrome native messaging starts one local Node process per Genius request. No server runs in the background. The registered host accepts only the extension origin and read-only public Genius search/song URLs; it has bounded frames, payloads and timeouts. The stable public manifest key preserves the packaged extension identity across folders.

Empty/error states expose a manual Genius search form. The authenticated `GENIUS_SEARCH` message reuses the same public-page reader as automatic fallback, validates a 2–200-character query and returns up to ten safe song choices without automatic identity filtering. Lyrics are fetched only after explicit selection. Pasted Genius song URLs use the existing validated page-loading path. Manual requests disable automatic replacement for that video; request generations reject stale results after another query or navigation. Query edits and keyboard focus survive responses. Successful lyrics hide the recovery form.

The UI renders only the song name, lyrics and options affordance by default. Settings and attribution are inside a bounded menu. Actual currentTime drives active lines; a 580ms requestAnimationFrame scroll retargets to the current line's geometry. Ordinary clicks do not disable following. Manual browsing pauses it for six seconds; reduced motion uses immediate positioning. Animation frames and timers are cancelled on state changes/disposal.

Editable search, URL and timing inputs are light-DOM children projected into the panel through named slots. They remain the actual `document.activeElement`, so player shortcuts recognize text editing even when capture handlers predate the panel. ARIA names preserve labels; explicit Enter handling submits the slotted search form. The early keyboard guard remains for controls inside Shadow DOM. Projected inputs are removed on disposal.

The YouTube entry requires an extension connection. Once initialized as an extension, a missing runtime or invalidated messaging context cannot fall back to cross-origin browser fetches. The panel explains the disconnected state and offers Reload YouTube. Its options display the compiled content-script version, independently of the extension manager's current manifest version. Loopback/source fixtures retain their explicit standalone path.


YouTube metadata → background LRCLIB lookup → conservative recording match or candidate choice → source-native lyrics and optional real timestamps → local Romanization → Shadow DOM panel → video-time synchronization.

Toolbar action → tabCapture stream ID → offscreen tab-only recording → single AudioContext output connection → release tracks and output context → AudD upload → recognized metadata → same lyric pipeline.

Every video change aborts/stales prior content requests, resets offsets and disposes synchronization. Background provider work has timeouts and serialized rate control; stale replies cannot overwrite the new video's UI. Audio has separate session IDs, cancellation on navigation/tab closure, bounded clip size, capture and request deadlines. Secret values are read only in trusted extension contexts. Dictionary data is bundled; no remote executable code is loaded.

UI uses native keyboard-accessible controls, normal-flow placement, reduced-motion support, manual scroll/follow recovery, light/dark themes and safe text rendering. Source attribution and generated-text notices remain visible. The sidebar does not overlay the video or remove recommendations.

`FullscreenLyrics` moves the existing Shadow DOM host into the current fullscreen player, reserves a bounded video area with scoped temporary CSS, and exposes a pointer-captured/keyboard-accessible divider and hide/show control. Fullscreen exit, navigation and disposal remove player attributes/styles and restore regular placement. Resize does not reload lyrics or replace the video.

Timed lines are native buttons. Their callback adds the current offset to the source timestamp, clamps into actual media seekable ranges (or finite recording duration), seeks and resumes playback/following. Untimed text stays non-interactive. The synchronizer tolerates browser microsecond rounding at timestamp boundaries. Delay input is clamped and rounded to tenths; no timestamps are fabricated or rewritten.

Playlist priority is enforced in the outer sidebar on every layout reconciliation, including late insertions and container replacement. Manual Genius links use page-derived identity after fixed-origin URL normalization; automatic matching stays strict. Delay editing separates live application from committed formatting. Optional provider failures preserve useful existing results, while query-specific overload and explicit global rate limits have different recovery behavior.

Focusing a manual song or Genius query pauses automatic metadata-driven lookup for the current video, preserving the draft and native focus across late title updates. Retry or navigation restores automatic lookup.
